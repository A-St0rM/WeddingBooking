# Mail goes out as a draft in the event manager's own mailbox, and signing stays manual

e-conomic's API cannot email quotes or offers at all — only invoices, and only at the moment of booking — so the system has to own the mail channel for everything sent before an invoice exists.

Rather than sending mail itself, the system creates a **draft** in the event manager's own mailbox with the PDF attached and the text filled in. He adds his personal sentence and presses send, and the mail lands in his sent folder like any other. Wedding customers are emotional and spending a large one-off sum; the brief is explicit that nothing may go out unreviewed and that the tone must not become robotic. Drafting also sidesteps having to authorise the system to send mail in the manor house's name, which is setup time we do not have.

Signing stays exactly as it is today: the couple receive the PDF, sign it, and return it by mail; the event manager marks the Booking as signed and uploads the signed file. We deliberately did **not** build a "click here to accept" page. For an agreement of this size, a home-made acceptance button is legally doubtful, and that is not our call to make on the manor house's behalf. If the manor house already uses a digital signing tool, this decision should be revisited.
